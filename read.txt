🛠️ Script Architecture Breakdown
1. Development & Local Server
"dev": "vite"
What it does: Starts the local development server using Vite.

How it works: Vite instantly serves your app with Lightning-fast Hot Module Replacement (HMR). When you edit .vue, .ts, or .tsx files in src/, only the changed modules are re-rendered in the browser without reloading the entire page.

Usage: npm run dev

2. Production Build Pipeline
"build": "run-p type-check \"build-only {@}\" --"
What it does: The main production build command that runs both TypeScript type checking and Vite bundling in parallel.

How it works:

Uses npm-run-all2 (via the run-p CLI command) to execute type-check and build-only concurrently.

{@} forwards any extra command-line arguments passed to npm run build directly down into build-only.

If type checking fails, the process stops with an error to prevent broken code from deploying.

Usage: npm run build

"build-only": "vite build"
What it does: Bundles your Vue, TypeScript, and asset files into optimized, minified static files inside the dist/ folder.

How it works: Vite uses Rollup under the hood to perform tree-shaking (removing unused code), code-splitting, CSS minification, and chunking for maximum web performance.

Usage: Usually called automatically by npm run build, but can be run independently if you want to skip type checks.

"preview": "vite preview"
What it does: Spins up a fast local web server to preview the built dist/ directory.

How it works: Serves the static output files generated by npm run build so you can test production behavior (like production API endpoints, cached assets, and routed paths) locally before deploying to live servers.

Usage: npm run preview

3. Code Quality & Type Safety
"type-check": "vue-tsc --build"
What it does: Performs a project-wide static type evaluation across all .ts files and Vue single-file components (.vue).

How it works: Standard TypeScript compiler (tsc) cannot read <template> sections inside .vue files. vue-tsc extends TypeScript to check types in both your Script and Template blocks without outputting JS files.

Usage: npm run type-check

"lint": "eslint src --ext .vue,.ts,.js --fix"
What it does: Audits code quality and automatically fixes styling or syntax errors across all source files.

How it works: Scans all .vue, .ts, and .js files in src/ against configured ESLint rules (like missing imports, unused variables, formatting inconsistencies) and applies automated fixes on disk via the --fix flag.

Usage: npm run lint

"format": "prettier --write src/"
What it does: Formats all files inside src/ to follow consistent code styling rules.

How it works: Prettier parses files and re-prints them according to strict code layout rules (indentation, single/double quotes, trailing commas, line wrapping).

Usage: npm run format

4. Git Hooks & Automated Staged Linting
"prepare": "husky"
What it does: Initializes Husky Git hooks in your repository.

How it works: Runs automatically right after npm install. Husky installs custom hooks into your local .git/hooks/ directory (such as pre-commit) so linting rules are enforced before code is committed to Git.

"lint:staged": "eslint --fix"
What it does: Runs ESLint automatic fixes specifically on files staged for Git commit.

How it works: Triggered by lint-staged configuration during a git commit. Instead of checking the whole repository (which is slow), it only runs ESLint on files you have modified and staged (git add).

"format:staged": "prettier --write"
What it does: Formats staged files with Prettier during pre-commit execution.

How it works: Ensures that every file committed to Git is automatically formatted without developers needing to run npm run format manually.
